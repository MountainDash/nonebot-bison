# 渲染产物与传输无关

渲染器的产出是一个**与传输无关的内容值**：有序的块序列，最小集合是文本、图片引用、可选的提及与回复。发送器负责把它翻译成自己那套消息 IR（SAA 的 `MessageSegmentFactory` 或 Alconna 的 `UniMessage`），并**声明自己的能力集**；不支持的内容按降级规则处理并记录，不允许静默丢弃。

## Considered Options

- **渲染器直接产出某个发送插件的 IR**：省掉一层，但渲染器从此必须知道「谁会发它」—— 同一张 B 站风格卡片就无法既走 SAA 又走 Alconna，而「我想发图片 A 但用 SAA 发」正是最常见的需求。
- **渲染器产出图片字节**：把所有内容压成图片，换来传输无关性，代价是文本不可复制、适配器无法做富文本、且每次改排版都要重渲染。
- **按渲染产物的类型决定使用哪个发送器**：把「用哪种传输」写成数据的形状，等于让一个纯函数（渲染）承担传输策略。

## Consequences

- 发送器的地址是 `send:<sender>`，**目的地**上有一个 `sender` 字段（默认 `saa`），由扇出站点决定走哪个地址。
- 发送器是 1:N 配对（所有发送器都接受同一种 `rendered` kind），因此不能用类型自动配对，必须「显式默认 + 目的地覆盖」。
- 中立集合必须保持**最小**（文本、图片、提及、回复，外加可选的附件）。每加一种块类型，就要问一遍「每个发送器支持吗」，所以新增块类型的门槛必须高。
- 「发送器能力不足」是一条**可见的降级**，不是异常：记 metric、记 `extra`、在 inspect 里能看到这个目的地过去 24 小时降级了多少次。
