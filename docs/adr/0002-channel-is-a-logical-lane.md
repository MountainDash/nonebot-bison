# 信道是逻辑车道，顺序由「单在途」保证

courier 不提供传输级全序，也不实现序列号、Resequencer 或乱序窗口。顺序来自一条结构性约束：**同一信道上同时至多一个包裹在途**。信道是一行持久状态，不是任务或队列对象；当前只使用**一个执行 worker**，不开放 worker 数量配置。

调度循环只选择与分派到期信道，不直接等待站点完成。站点执行必须有有限超时；关闭时在排干期限后取消并等待任务真正结束。就绪信道必须公平调度，不能让持续可到期的信道饿死其他信道。

## Considered Options

- **序列号 + Resequencer**：需要额外的超时策略，而在超时那一刻必须在「乱序发出」与「阻塞车队」之间二选一。
- **单全局队列**：跨目的地队头阻塞，即 [#678](https://github.com/MountainDash/nonebot-bison/issues/678) 的成因 —— 一个群坏掉，所有群排队。
- **每目的地一个 task + 队列对象**：语义相同，但物理开销随目的地数增长，且队列状态不在存储里，既不能活过重启（[#635](https://github.com/MountainDash/nonebot-bison/issues/635)）也不能被 inspect。
- **当前开放多 worker**：在「只取 head」之外还需要数据库原子 claim、崩溃回收与 fencing；现有规模没有提出这项需求。

## Consequences

- 最终顺序只承诺到**同一源、同一订阅、同一有效配置代际（effective_revision）**；不同源之间不承诺按内容时间形成全序。扇出批次必须由有序序列给出，不能使用无序集合表达顺序。
- 失败在原信道重试，只推后该信道的 `next_attempt_at`。渲染降级也在原渲染站点内完成，不另开一条可能超车的渲染路径。
- **跨信道不再承诺「永不互相等待」**。单 worker 的执行耗时会带来有界等待；正确性要求是任何失败、超时或退避都不能造成其他信道的无界阻塞。
- 信道的 head、尝试计数与 head 错误只是当前包裹的投影；推进时从下一个 Receipt 重建，不沿用旧计数。`resource_available_at` 是独立的资源持久状态，不属于 head 投影，换 head、空 lane 与重启均不得清零。held 包裹保留顺序但不占活动 head。
- 将来若开放多 worker，必须先以新的决策定义原子 claim、租约到期、崩溃 reclaim 与 fencing，不能把内存锁当作持久化保证。
- 队列必须落表。信道成本是一行状态，因此「按资源划分信道」不依赖每信道一个常驻任务。
