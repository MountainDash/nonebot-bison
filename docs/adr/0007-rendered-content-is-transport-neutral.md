# 渲染产物与传输无关，降级与具体渲染技术无关

渲染器的产出是一个**与传输无关的内容值**：有序的块序列，最小集合是文本、图片引用、可选的提及、回复与附件。发送器把它翻译成自己的消息 IR，并声明能力集；不支持的内容必须沿明确的降级链处理，不能静默丢弃。

核心不认识浏览器、Canvas 或任何具体渲染技术。Renderer 自己拥有并释放其资源，把内部异常翻译成通用错误类别；通用流水线只负责有限超时、取消、重试与降级。浏览器型 Renderer 的 page/context/process 清理是该组件的实现契约，不进入核心分支。

## 渲染计划与降级

有效渲染计划包含内容身份与 effective_revision、Renderer 身份、完整解析后配置、Renderer 实现版本、Sender 能力集和降级变体。**同一计划只渲染一次；不同能力变体可以分别渲染。**

- 可重试失败先消耗重试预算，耗尽后在**原渲染站点内**降级；可降级的永久失败立即降级。
- 降级链是「指定 Renderer → `basic` → 最终纯文本」。`basic` 是**文字与动态原生媒体**，不要求卡片渲染或浏览器；媒体不可用或 Sender 不支持媒体时，才退到纯文本。
- 降级不另投一条 Renderer 信道，避免后续内容借其他路径超车。最终纯文本也失败才进入死信。
- Sender 瞬态失败只重试发送，不改变内容；Sender 与 destination.adapter 不兼容属于启动期装配错误。关闭导致的取消保留包裹，不触发降级。

## Considered Options

- **Renderer 直接产出某个发送插件的 IR**：Renderer 从此必须知道传输方，无法让同一风格跨 Sender 复用。
- **把所有内容压成图片**：文本不可复制，适配器无法使用富文本，改排版也必须重渲染。
- **按产物类型决定 Sender**：让纯渲染承担传输策略。
- **在 Sender 临时丢弃不支持的块**：产生静默或难以归因的内容损失，也无法完成「指定 Renderer → basic」的重渲染。
- **把浏览器纳入核心模型**：会把某一个 Renderer 的实现细节泄漏给所有组件。

## Consequences

- Sender 采用「显式默认 + 目的地选择」，不能由所有 Sender 都接受的 `rendered` 类型自动配对。
- 中立块集合保持最小；新增块类型必须同时说明各 Sender 的能力与降级方式。
- 每次降级都产生系统事件，记录 subscription、destination、renderer、sender、原变体、目标变体与原因，并投影到指标和 inspect；不写入 Enricher 专属的 `extra`。
- 组件执行超时必须可取消并等待清理完成，否则单 worker 仍会被卡住，降级逻辑也没有执行机会。
